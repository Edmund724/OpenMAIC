# P1：课堂对话面板原型

Type: prototype
Status: resolved
Blocked by: —

## Question

把已经拍板的形状做成**可点的原型**，让用户看着点一遍，确认观感。要回答的不是"能不能做"，而是"长这样对不对、手感对不对"。这是本 effort 里最大的一块，也是唯一能一次清掉大片迷雾的动作。

原型必须能走通这几条路（假数据即可）：

1. **对话屏**：消息流（学生 / 老师 / 学生 agent 三种气泡）+ 底部常驻输入区（文本域、麦克风、发送、引用课件入口）。**不要**模型选择、联网搜索、建议问题卡。
2. **录音态**：点麦克风后输入区**原地**变形（波形 / 识别中 / 取消），识别结果**落进输入框**而不是直接发送。
3. **历史屏**：面板内两屏切换；列表按"今天 / 昨天 / 更早"倒序分组；条目 = 标题（学生首句）+ 时间 + 类型与状态小图标；"新对话"按钮；条目上的重命名与隐藏。
4. **"轮到你了"**：输入区高亮 + 对话 tab 上的琥珀点。
5. **空对话屏**：新开一段对话时看到的画面。
6. **舞台侧**：横条右栏（麦克风 / 气泡按钮 / 头像）撤掉之后两栏横条的样子，以及全屏讲课时舞台上那套输入条。

原型要让人一眼看出"和现在的差别在哪"，所以**改造前后要能对照**（并排或一键切换）。

开工前先读 R1 的产出（若已就绪）。产出位置：仓库内一个独立原型路由（如 `/prototype/classroom-chat`），只读假数据，**不碰现有课堂逻辑**——`components/roundtable/`、`components/chat/use-chat-sessions.ts`、`components/edit/PlaybackChromeRoot.tsx` 一行都不改。开工前调 Skill: prototype。

## Answer

用户选定**变体 B（历史浮层）**：对话常驻，历史从面板顶部盖下来一层浮层，学生永远不离开对话屏；被否掉的 A（两屏切换）与 C（上下分栏）留在原型里备查。

附带定下（用户看过原型后当场提出的修改）：

- **全屏讲课的输入条移进右侧黑框**，不放舞台中央——幻灯片区之外，任何屏幕比例下都不遮挡课件。
- 全屏形态下输入条**收成窄栏**（按钮只留图标），因此面板输入框与全屏输入条是同一个组件的两种形态（`compact` 开关），草稿仍互不共享。
