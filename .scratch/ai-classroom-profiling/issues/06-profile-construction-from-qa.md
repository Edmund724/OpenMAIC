# T3：画像构建机制——问答对话如何进画像

Type: grilling
Status: resolved
Blocked by: 02, 05

## Question

定画像的构建与更新机制，重点是用户的核心痛点：学生与 AI 助教的问答对话如何转化为画像。候选机制（来自 R2 调研）：LLM 观察分类 + 确定性入账（OpenMAIC 模式的扩展）、周期性 summarization agent（MAIC 论文模式）、对话行为分类、从对话原文估计知识状态。定：MVP 用哪种或哪几种组合、更新时机（实时/课末/阶段性）、置信度与纠错机制、冷启动（新生第一课的画像从哪来：摸底测验/自报/默认值）。

参照：`.scratch/ai-classroom-profiling/research/02-dialogue-student-modeling.md`；OpenMAIC"LLM 观察、代码计分"模式见调研报告 4.2 节。会话开场调 Skill: grilling + domain-modeling。

## Answer

2026-09-20 经一轮 grilling 全部按推荐拍板：

1. **机制总架构：分层制**。LLM 只做"判断"（提问类型分类、对话涉及概念标注、逐轮理解/误解判定），画像数值的演化全部由确定性规则完成——可复现、可单测、可审计。拒绝 LLM 直出画像数值（与 T2"每字段带证据来源"纪律冲突）。
2. **掌握度模型：BKT（贝叶斯知识追踪）**。每概念一个掌握概率；证据输入 = 测验逐题作答 + 对话中 LLM 标注的"涉及概念 × 理解/误解"；参数用经验先验起步，不需训练管线。远期升级路径：积累数据后换专门 KT 模型。这完成 OpenMAIC"单轴 tier"到"逐概念向量"的跨越。
3. **更新时机**：对话行为标签 = 会话末 LLM 批量打标入账（带全上下文、成本可控）；测验提交 = 立即更新相关概念掌握度（结构化、零延迟）；课中即时适应不走画像管道，由助教对话上下文承担（归 T5）。
4. **冷启动**：入课自报对话（PAGE 式，必做，身份层唯一来源）+ 摸底诊断测验（教师组 10–15 题覆盖主干概念，喂 BKT 先验）+ 未覆盖概念默认中值低置信兜底。
5. **置信度与纠错**：置信度 = 证据计数 + 时间衰减的确定性函数；学生显式声明（"这个我早会了"/"完全不懂"）按强证据高权重入账；教师 MVP 不能直接改画像数值，只能修正知识图谱/题目标注/模块挂接来间接纠错，直接编辑放远期。
6. **身份层周期性重提炼**：每学习阶段末 summarization agent 重读近期对话重提炼身份/兴趣标签，更新前给学生看摘要、确认后生效（PAGE"修正优先"原则）；状态层/行为层纯增量入账，不用此机制。
