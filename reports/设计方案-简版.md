# AI 课堂学生画像与分层教学设计蓝图（简版）

---

## 第 0 章 总览

设计闭环：

```
交互采集（事件信封，全量原文）
   → 学生画像（身份层 / 行为层 / 状态层，每个字段都有证据来源）
   → 分层教学（补基础 / 加速 / 加深，内容级插拔 + 助教策略调整）
   → 闭环评估（学习成效 / 机制健康 / 体验三层指标）
   → 回调（阈值校准、打标抽检、模块质量），回到采集与策略
```

与 OpenMAIC 的三点根本差异：

1. **画像是三维的**（他是谁 / 他怎么学 / 他现在会什么），OpenMAIC 只有一维难度档；
2. **问答对话是画像的核心原料**：学生问了什么、怎么问、在哪卡住，全部转化为画像证据，不躺在聊天记录里；
3. **个性化是内容级的**：为基础薄弱者沿先修链插补习模块、为学得快者跳过已掌握内容并追加深化模块，不限于对讲稿做 token 级润色。

**MVP 与远期速查表**

| 层     | MVP 必做                                                                                          | 远期                                                        |
| ------ | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 采集   | 统一的行为记录格式；问答全文连同"提问时学到哪"一起存；记录视频看到哪、课件每页停多久、测验每题用时与改答案过程 | 利用学生在课件里的高亮和批注                                |
| 画像   | 三层画像（身份/行为/状态）；每次学习结束由 AI 给对话做标注；逐概念掌握概率；新生靠"自我介绍 + 摸底小测"起步 | 识别困惑/挫败等情绪；更细的提问行为分析；用专门模型替换经验公式 |
| 内容   | AI 从课程材料抽取概念图谱、教师过目确认；AI 生成补习内容；学有余力者在课内加深                      | 拓展到课程之外（前沿论文、工程实践）                        |
| 策略   | 补基础/加速/加深三种动作的自动触发规则；助教按三种状态调整讲法                                    | 整门课大纲按学生情况重新排序                                |
| 评估   | 三层指标的持续观察；教师定期校准触发线、抽检 AI 标注质量                                          | 分学生做对比实验；自动调参                                  |
| 教师端 | 班级聚合三件套（卡点排行、触发统计、全班掌握热力）+ 每个学生的掌握地图                            | 教师直接修改画像；个体辅导工作台                            |

## 第 1 章 设计目标与原则

### 1.1 产品定位

单课程 AI 课堂：左侧课件区（视频、PPT、PDF），右侧 AI 助教，学生随学随问。面向理工科大学生（先修链条硬、概念密度高的学科）。课程内容由教师上传，AI 在其上做答疑、采集、画像、分层；教师承担内容提供者与质量审校者两个角色。一切画像与自适应在一门课的边界内闭环，不做跨课程联动。

### 1.2 从 OpenMAIC 的三个短板到三个目标

OpenMAIC 是 MAIC 论文的开源实现，采集与调度在公开项目中最完整，但有三个结构性短板：

- **画像太浅**：开源版的"画像"是手填简介 + 单轴熟练度档（指数滑动平均）+ 单次项目统计；论文宣称的"对话采集 + 摘要 agent + 结构化标签画像"完全不存在。
- **问答不进画像**：全量对话存了（这做得对），但画像数值只消费测验分等结构化信号，对话原文从未入账；论文自己证明了对话行为与成绩显著相关，系统却没用。
- **个性化过于克制**：所有学生看同样的课件、顺序和题，画像只改"怎么讲"，不改"讲什么、补什么、跳过什么"。

对应的三个设计目标：

1. **多维三层画像**：身份层、行为层、状态层，每个字段标注证据来源；
2. **问答成为画像的核心原料**：每轮对话被标注、入账，转化为提问构成与逐概念掌握度；
3. **内容级分层教学**：补基础沿先修链、加速跳过已掌握、加深按求知欲分流，形成"采集 → 画像 → 课堂改变 → 评估回调"闭环。

### 1.3 五条贯穿原则

1. **分层制：LLM 只做判断，数值由确定性规则演化。** LLM 判断提问类型、涉及概念、理解或误解；掌握概率、置信度、阈值的每步演化都由确定性规则完成。理由：可复现、可单测、可审计、可回放证据链，LLM 直出数值做不到。
2. **每个画像字段必须标注证据来源。** 写不出"由哪类采集事件喂养"的字段不允许存在，防止画像膨胀成无据可依的字段清单。
3. **采集与画像一体设计，信封先行。** 统一事件信封，所有指标从信封派生，不单独埋点。反面教材：MAIC 论文宣称的"10 万+ 行为记录"连字段定义都没给出。
4. **教师在环，只做审校与聚合消费。** 审校图谱、抽检打标、固化高频模块、校准阈值；不看学生对话原文，不直接编辑画像数值。AI 做体力活，教师做质量兜底。
5. **学生主体性不可剥夺。** 主线内容始终可见，补习是插入不是替换；学生显式声明是强证据；学生能看到自己的概念掌握地图。分层教学是服务，不是分班。

## 第 2 章 交互采集层

立场：采集是画像的原料采购，只采有明确画像消费方的信号，写不出消费方的字段一律不采。

### 2.1 事件信封与派生层

```
{ 事件ID, 学习者ID, 会话ID, 时间戳, 课程ID, 资源定位, 事件类型, 载荷 }
```

- **资源定位**是关键字段：视频到秒、PPT/PDF 到页、测验到题、对话到当时的课件位置。没有它就无法挂接概念图谱、喂养画像。
- **会话ID** 是"首看/重看""学习节奏"等派生统计的分界。
- 事件流只追加、不修改、可重放；课程时长、活跃天数、完成率、首次作答正确率（CFA）等指标全部从信封派生，不单独埋点。派生逻辑可改可重算，原始事件不动。

### 2.2 四族采集

- **问答对话（最富的信号源，采到最细）**：每条消息存全文，带时间戳、会话 ID、课件上下文（提问时学到哪里、涉及哪个概念）；点选课件元素提问时记录被引用元素。提问分类、概念标注、理解/误解判定是会话末批量计算的派生层，采集层只保证原料完整。坚持全量原文的理由：研究已证明对话文本里的行为结构与成绩相关、从原文估计逐知识点掌握可行，且只有原文能支撑未来还没想到的用法。
- **视频**：xAPI Video Profile 子集（播放、暂停、拖动、完成、倍速变更）；在暂停/拖动/完成/页面隐藏时事件驱动地记录观看区间，不做定时心跳；标签页切换记一次暂停。判读纪律（在派生层）：首看与重看分开统计（重看是选择性观看，热区标记困惑点或兴趣点，不能直接定性"没学会"）；开头瞬时退出按噪声过滤；倍速不作负面解读（≤2x 对理解成绩无显著损害）。
- **课件（PPT/PDF）**：页级翻页 + 页级可见停留（标签页失焦不计时）。停留时长只有细粒度 + 可见性过滤才有效；播放器已支持高亮/批注则顺带采集，不专门开发。
- **测验**：逐题用时 + 答案修改轨迹（修改前后选项 + 次序）。首次修改方向（错→对约占 48–55%）是有效的元认知信号，第二次及以后基本是噪声。

### 2.3 不采清单与身份边界

- **不采**：光标轨迹、滚动深度、鼠标移动（噪声大、文献无价值共识、隐私敏感）。每个新增字段必须重过"画像消费方是谁"的审查。
- **账号制**：画像跨设备、跨会话连续。OpenMAIC 的匿名设备 key 换设备即断，弃用。
- **对话原文属敏感数据**：与派生的画像字段分离存储，学生可请求删除。
- **教师边界**：教师只见聚合层与个体掌握地图，永远不见个人对话原文与行为标签。

OpenMAIC 有两个值得继承的采集设计：事件产生于服务端而非前端埋点（本设计改造为"会话末批量打标"）；只追加、可重放的事件账本（与事件信封同构）。

## 第 3 章 学生画像层

### 3.1 三层骨架

画像 = 身份层（他是谁）+ 行为层（他怎么学）+ 状态层（他现在会什么），每个字段标注证据事件类型。

**身份层（静态，低频更新）**

| 字段       | 形状                 | 证据来源                    | 用途限定                                       |
| ---------- | -------------------- | --------------------------- | ---------------------------------------------- |
| 课程身份   | 年级/专业/先修课自述 | 入课自报对话                | 冷启动先验 + L1 语境化，**不作难度判断主依据** |
| 兴趣标签树 | 域/类/关键词三级标签 | 入课自报对话 + 阶段末重提炼 | L1 举例与类比的素材库                          |

**行为层（构成向量，会话末更新）**

| 字段       | 形状                                               | 证据来源               | 含义                                                       |
| ---------- | -------------------------------------------------- | ---------------------- | ---------------------------------------------------------- |
| 提问构成   | 概念性提问 vs 任务特异提问的比例（滚动）           | 会话末打标（对话原文） | 最强预测轴：概念性提问与成绩正相关，任务特异求助是困惑信号 |
| 投入度聚合 | 每周活跃天数、视频完成率、首看/重看比              | 视频/课件事件派生      | MOOC 预测中复现性最好的特征族                              |
| 测验过程   | CFA（首次作答正确率）、首次修改方向                | 测验事件派生           | 元认知信号                                                 |
| 求知欲     | 弱信号分（主动提问频次、概念性提问占比、主动重看） | 派生                   | 加速 vs 加深的分流依据                                     |

**状态层（动态估计，测验即时 + 会话末更新）**

| 字段         | 形状                                                | 证据来源                    | 含义                         |
| ------------ | --------------------------------------------------- | --------------------------- | ---------------------------- |
| 逐概念掌握度 | 每概念 `{掌握概率 0–1, 置信度, 证据计数, 最近更新}` | 测验逐题作答 + 对话理解标注 | 补基础/加速/加深的全部触发源 |
| 学习速度     | `{单位活跃时长掌握概念数, 每概念平均练习轮次}`      | 掌握度历史派生              | 区分"掌握得快"与"慢慢磨会"   |

设计说明：

- **提问构成是行为层的第一公民**：提问指向通用概念还是当前任务，是比消息量值钱得多的切分轴；OpenMAIC 只统计了消息量，恰好丢掉了这个轴。
- **求知欲单列**是分流逻辑需要：掌握高且求知欲高给加深，掌握高但求知欲低只加速。它是派生弱信号；显式情感检测投入产出比在单课程场景不成立，放远期。
- **学习速度用绝对度量**，不用班级百分位：单课程初期没有稳定对照群体，且百分位会把"全班都快"误判成"没人快"。
- 31 类完整对话行为分布放远期，MVP 先把最有预测力的轴做扎实。

### 3.2 构建机制：分层制的运转

- **LLM 只做三类判断**：① 提问类型（概念性/任务特异/其他）；② 涉及概念（挂图谱概念 ID）；③ 理解还是误解。画像数值演化全由确定性规则完成，拒绝 LLM 周期性读对话直出画像数值。
- **打标时机：会话末批量。** 带完整上下文对整段会话打标，能看到"学生最后懂了没有"，成本更低、失败可重跑。课中即时适应由对话上下文直接支撑，画像不背实时压力。
- **掌握度模型：BKT。** 每个概念一个掌握概率，两路证据入账：测验逐题作答（强）、对话理解标注（弱）。参数用经验先验起步，升级路径：经验参数 BKT → 拟合参数 → 专门 KT 模型。相对 OpenMAIC 的单轴档位，这是从"一个数"到"逐概念向量"的跨越，补基础因此能精确到概念。
- **更新时机**：测验提交立即更新；对话标注会话末更新；行为层会话末派生；学习速度滚动窗口派生（证据不足不显示）。

### 3.3 冷启动

- **入课自报对话（必做）**：年级、专业、先修课、兴趣，身份层唯一来源。借鉴 PAGE 的做法：固定开场、必答项追问、每兴趣限一次追问、学生确认后生效。
- **摸底诊断测验（建议做）**：教师组 10–15 题覆盖主干概念，直接喂 BKT 先验，让补基础/加速从第一节课就可用。
- **默认兜底**：未覆盖概念掌握概率取中值、置信度取低，等证据说话。

### 3.4 置信度与纠错

- **置信度 = 证据计数 + 时间衰减的确定性函数**；低置信概念不触发任何教学动作（宁可不动作，不可错动作）。
- **学生显式声明 = 强证据**，按高权重直接入账。
- **自我修正通道**：被标弱的概念在后续测验中抽样再现（再挑战机制），证据持续冲刷旧判断。
- **教师不直接改数**：只能通过修正图谱、题目标注、模块挂接间接纠错，保住可审计性；直接编辑放远期。

### 3.5 身份层的周期性重提炼

自述型数据会过时。每个学习阶段末，摘要 agent 重读近期对话，重提炼身份/兴趣标签；更新前给学生确认（修正优先：学生纠正过的内容以最终版为准）。状态层与行为层纯增量入账，不做全量重提炼。

### 3.6 学生可见性

- **可见**：概念掌握地图（自我导向复习，也让错误画像有机会被学生发现）、进度与投入摘要。
- **不可见**：置信度内部值、提问行为标签。行为标签一旦公开就会成为刷取目标，指标即失效（古德哈特定律）。

## 第 4 章 内容地基：知识图谱与模块体系

L2 内容级自适应的前提是课程内容可拆换，三件事：

- **概念知识图谱**：每门课 100–300 个概念节点 + 先修有向边（章节树保留为组织外壳）。AI 从教师材料自动抽取，教师发布前审校（只看低置信边与主干链）。**图谱版本化**：概念 ID 稳定，修改 = 新增/废弃，画像证据挂在概念 ID 上，图谱迭代不得毁掉既有画像。
- **两张映射**：概念 → 材料片段（补基础时指回原文重看）；概念 → 测验题（BKT 的证据入口）。
- **模块体系**：模块 = 单概念或 ≤3 概念小簇，类型为讲解/练习/讨论，标注层级（补基础/标准/深化），挂概念 ID 供策略引擎调用。补习模块由 AI 生成（讲解 + 重看指引 + 2–3 题巩固），高频模块教师审校固化；深化模块 MVP 只做课内加深，开放外拓放远期。

## 第 5 章 分层教学策略：L2 闭环

触发是确定性规则引擎（阈值+置信度+冷却），LLM 只负责动作内容。三态：

- **补基础**：双通道触发——学新内容前沿先修链检查依赖概念（掌握 <0.6 且置信足够，事前预防）；测验错误或对话标注误解（事后补救）。动作 = 插入补习模块 + 助教补基础态，插入不替换、主线始终可见。补后测通过即回主线；两轮未过沿先修链再降一层，该概念同时进教师聚合视图（群体卡点是课程问题）。
- **加速**：掌握 ≥0.85 且置信足够 → 标准讲解替换为摘要卡 + 3 题确认测，通过即跳过（确认测是防掌握度高估的闸口）。
- **加深**：掌握高且求知欲高 → 追加深化模块 + 助教加深态；掌握高但求知欲低只加速不加深。
- **L1 助教策略查表**（三态共用）：补基础态更慢更多例子、提示式引导优先于直接给答案（证据：提示式回应显著提升学习率，直接给答案为负）；加速态精简；加深态苏格拉底反问；全程兴趣类比。
- **防标签固化四护栏**：置信度+时间衰减；学生声明强证据；插入不替换；再挑战通道。

## 第 6 章 闭环评估

- **三层指标**：学习成效层（掌握度曲线、达标耗时、阶段成绩）；机制健康层（补习触发率、补习后回归成功率、加速确认测通过率、深化模块完成率，负责发现"自适应系统自己病了"）；体验层（投入度趋势、概念性提问占比变化）。
- **节奏**：机制健康层持续可查，三层指标每模块末例行回顾，课程结束整体评估。
- **第二阶闭环**：阈值校准（0.6/0.85 为待校准初始值）、LLM 打标小比例人工抽检、低回归率模块进教师队列。MVP 由教师在环执行，不做自动调参。
- **严谨度立场**：观察性指标 + 透明口径起步，不设对照组（样本量与伦理双重原因）；存储预留按学生分桶的能力，A/B 放远期。
- **教师端视图（MVP）**：班级聚合三件套（卡点概念排行、三态触发统计、全班掌握热力）+ 个体掌握地图；不见对话原文与行为标签。

## 第 7 章 分期路线

**MVP**：采集四族 + 信封；三层画像 + BKT + 冷启动；图谱 + 补习/深化模块；三态策略；三层指标 + 教师端视图。

**MVP 推进顺序与时间线**（起点：已有基础界面与基础 AI 问答）

先做什么后做什么，由数据流向决定：学生的行为先被记录下来，才能算出画像；有了画像，才能决定给谁补基础、给谁加速；课堂真的发生变化后，才谈得上评估效果。所以建设的顺序就是自下而上：先记录、再画像、再分层、最后评估。唯一的例外是概念图谱——它不和采集抢时间，但画像、策略都要引用图谱里的概念编号，所以必须尽早启动、尽早把编号定下来。

| 阶段 | 做什么（用大白话说）                                       | 前置条件                | 估时（人周） |
| ---- | ---------------------------------------------------------- | ----------------------- | ------------ |
| 1    | 定一套统一的行为记录格式，建一本"只增不改"的行为台账；给现有问答补上"提问时学到哪了"这条上下文 | 无                      | 1~1.5        |
| 2    | 在视频、课件、测验里加行为记录：看了哪段、每页停了多久、每题做了多久改没改答案 | 1                       | 1.5~2        |
| 3    | 建课程的概念图谱：AI 从教师材料里抽出概念和先后关系，教师过目确认；同时把概念和课件位置、测验题对应起来 | 无，可与 2 同时做       | 2            |
| 4    | 做画像：每次学习结束后 AI 给这段对话做标注，再结合测验成绩，算出每个概念的掌握概率；新生用"自我介绍 + 摸底小测"起步 | 1、2 提供数据，3 提供概念编号 | 2.5~3        |
| 5    | 做分层教学：按画像自动触发三种动作——没跟上的插补习、已掌握的跳过、学有余力的加深（开发顺序也按这个排） | 3、4                    | 2~3          |
| 6    | 做评估与教师端：统计补习有没有效果、给教师看全班卡点分布图、给学生看自己的掌握地图 | 前面全部，部分可与 5 同时做 | 1.5~2        |

- 一个人从头做到尾约 **10~13 周**；两个人分工（一人做行为记录、一人做概念图谱，后期一人做分层、一人做教师端）约 **6~8 周**。前提：开发者熟悉现有代码、AI 接口现成、教师自己准备课程材料和摸底题。
- 时间紧的话，阶段 2 里测验可以先只记"每题用时和对错"，"改答案的过程"以后补——它只是个辅助信号，不影响主流程。
- **强烈建议先用 4~5 周打通一条最小链路，再补全其余部分**：只做"记录问答 → AI 标注 → 算出十几个核心概念的掌握度 → 给没掌握的学生插补习"这一条线，教师端先只给一张掌握情况热力图。这样最容易出问题的三个环节（AI 标注准不准、掌握度算法合不合理、概念和课件的对应对不对）能在最早的时候暴露；验证可行后，再补视频和测验的记录、加速和加深两种动作、完整的评估报表。

**远期项与启动条件**：

| 远期项                | 启动条件                                   |
| --------------------- | ------------------------------------------ |
| L3 路径级大纲重排     | 加速/补基础高频发生，内容级插拔显局促时    |
| 开放外拓深化模块      | 课内加深被反复触发且学生要求超出课程范围时 |
| 显式情感检测          | 有明确证据显示困惑/挫败导致流失时          |
| 31 类完整对话行为分布 | 提问构成轴验证有效、需要更细行为画像时     |
| 专门 KT 模型          | 积累足量标注数据、BKT 拟合不足时           |
| 分桶 A/B              | 学生规模达到统计功效要求时                 |
| 教师直接编辑画像      | 教师端使用成熟、出现明确误判诉求时         |

## 第 8 章 与 OpenMAIC 的总对照

| 维度       | MAIC 论文（宣称）              | OpenMAIC（开源现实）                        | 本设计                                                    |
| ---------- | ------------------------------ | ------------------------------------------- | --------------------------------------------------------- |
| 交互采集   | 10 万+行为记录（无字段定义）   | 消息+课件快照、engagement 账本、quiz 三阶段 | 统一事件信封四族采集，问答全量原文+上下文，测验带过程数据 |
| 画像维度   | 学术+情感结构化标签            | 手填简介 + 单轴难度档                       | 身份/行为/状态三层，逐概念掌握度+学习速度+提问构成        |
| 建模技术   | 对话 agent + 摘要 agent        | LLM 观察 + 确定性滑动平均                   | 分层制：会话末 LLM 打标 + BKT 确定性入账                  |
| 问答利用   | 未打通（画像只服务改写）       | 存而不用                                    | 核心原料：提问构成、概念理解双路入账                      |
| 个性化层级 | token 级改写（不改变教学内容） | 档位注入提示词                              | L1 三态策略查表 + L2 内容级插拔（补/跳/加深）             |
| 闭环       | 未做 on/off 对照，证据链断裂   | 无评估层                                    | 三层指标 + 第二阶闭环，阈值可校准                         |

**继承**："LLM 观察、代码计分"的分层思想（推广到全画像层并升级为 BKT）；只追加、可重放的事件账本；服务端产生学习事件（改造为会话末批量打标）；学生显式声明即 ground truth。论文侧的 PAGE 自报对话与摘要重提炼、提示式引导优于直接给答案的证据、概念性/任务特异提问切分轴，直接进入对应层。

**修正**：画像从单轴难度 + 手填身份到三层多维；问答从"存而不用"到采集与画像的正中央；个性化从 token 级改写到内容级插拔为主目标（L1 作为三态策略的副产物落地）；评估补上机制健康层与第二阶闭环，论文断裂的个性化证据链变成持续可答的问题。

**新增**：概念知识图谱 + 模块体系（AI 抽取 + 教师审校 + 版本化）；机制健康层指标体系；求知欲分流（OpenMAIC 的单轴结构在原理上无法表达加速与加深的分离）。

## 附录

### 附录 A 术语表

- **画像**：多维、随学习演进的学生模型，分身份层/行为层/状态层。
- **事件信封**：全部采集事件共用的统一字段头（学习者/会话/时间戳/课程/资源定位/事件类型/载荷）。
- **派生层**：从原始事件可重算的指标与标签，不在采集时锁死。
- **分层制**：LLM 只做判断、画像数值由确定性规则演化的架构原则。
- **BKT**：贝叶斯知识追踪，逐概念掌握概率的更新模型。
- **先修链**：概念间的先修有向边，补基础沿它回溯。
- **补习模块/深化模块**：挂在概念 ID 上的可调换内容单元（讲解/练习/讨论，≤3 概念小簇）。
- **三态策略**：补基础态/加速态/加深态的分层教学动作族，由确定性规则引擎按画像触发。
- **三层指标**：学习成效/机制健康/体验三族评估指标。
- **第二阶闭环**：评估结果回调阈值、打标质量与模块质量的机制。
- **L1/L2/L3**：对话级/内容级/路径级自适应。
