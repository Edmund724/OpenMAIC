# AI 课堂学生画像与分层教学设计蓝图

---

## 第 0 章 总览

本设计围绕一条闭环展开：

```
交互采集（事件信封，全量原文）
   → 学生画像（身份层 / 行为层 / 状态层，每个字段都有证据来源）
   → 分层教学（补基础 / 加速 / 加深，内容级插拔 + 助教策略调整）
   → 闭环评估（学习成效 / 机制健康 / 体验三层指标）
   → 回调（阈值校准、打标抽检、模块质量）——回到采集与策略
```

与 OpenMAIC 的根本差异可以压缩成三句话：

1. **画像是三维的**（他是谁 / 他怎么学 / 他现在会什么），不是一维的难度档；
2. **问答对话是画像的核心原料**——学生问了什么、怎么问、在哪卡住，全部转化为画像证据，而不是躺在聊天记录里；
3. **个性化是内容级的**——为基础薄弱者沿先修链插入补习模块、为学得快者跳过已掌握内容并追加深化模块，不是只对讲稿做 token 级润色。

**MVP 与远期速查表**

| 层     | MVP 必做                                                                            | 远期                                              |
| ------ | ----------------------------------------------------------------------------------- | ------------------------------------------------- |
| 采集   | 事件信封；问答原文+上下文；视频 xAPI 子集；课件页级翻页+可见停留；测验逐题+修改轨迹 | 课件内高亮/批注的深度利用                         |
| 画像   | 三层骨架；会话末 LLM 打标；BKT 掌握度；冷启动三件套                                 | 显式情感检测；31 类完整对话行为分布；专门 KT 模型 |
| 内容   | 概念图谱（AI 抽取+教师审校）；补习模块 AI 生成；课内加深                            | 开放外拓（前沿论文/工程实践）                     |
| 策略   | 补基础/加速/加深三态规则引擎；L1 三态助教                                           | L3 路径级大纲重排                                 |
| 评估   | 三层指标观察性跟踪；第二阶闭环（教师在环）                                          | 分桶 A/B；自动调参                                |
| 教师端 | 班级聚合三件套 + 个体掌握地图                                                       | 教师直接编辑画像；个体辅导工作台                  |

## 第 1 章 设计目标与原则

### 1.1 产品定位

本产品是一个单课程 AI 课堂：左侧是课件区（视频、PPT、PDF 均可），右侧是 AI 助教，学生随学随问。课程面向大学生，学科为理工科（人工智能、深度学习、集成电路、微电子等——先修链条硬、概念密度高的领域）。课程内容由人类教师上传，AI 在教师的内容之上发挥作用：助教答疑、采集交互、构建画像、分层教学。教师不是旁观者，而是内容的提供者与质量的审校者。

"单课程"是一个重要的范围约束：本设计不考虑跨课程画像联动，一切画像与自适应都在一门课的边界内闭环。

### 1.2 从 OpenMAIC 的三点批判到三个设计目标

OpenMAIC 是清华 MAIC 论文的开源实现，是目前多智能体 AI 课堂中采集与调度做得最完整的公开项目。但从"用交互数据驱动学生画像、用画像改变课堂"的视角看，它有三个结构性短板，本设计的三个目标正是对着这三个短板立的：

**短板一：画像太浅。** OpenMAIC 的"学生画像"实际由三块构成：学生手填的昵称/简介（静态、不演进）、一个单轴的熟练度档位（初级/中级/高级，由测验正确率和课堂事件经一套指数滑动平均规则驱动）、以及单次项目的过程性统计。论文宣称的"对话采集 + 摘要 agent + 结构化标签画像"（学术特征 + 情感特征）在开源版完全不存在。兴趣、学习风格、认知特点等维度全部缺失。

**短板二：问答对话完全不进画像。** OpenMAIC 把学生的全量对话都存了下来（这是它做得对的地方），但画像的数值演化只消费结构化信号（测验分、LLM 打的少数几类观察标签），对话原文——学生问了什么、问的是概念还是操作、在哪一步卡住——从未被转化为画像。论文第 5 章自己证明了对话数据的价值（每模块消息数、消息长度与成绩显著正相关），系统却没有用。

**短板三：个性化过于克制。** 无论是论文的 token 级改写（检索 + 按 Bloom/ZPD/UDL 三理论润色讲稿），还是开源版的"档位变化注入提示词"，课堂内容本身是不变的：所有学生看同样的课件、同样的顺序、同样的题。画像只改变了"怎么讲"，没有改变"讲什么、补什么、跳过什么"。

**对应的三个设计目标：**

1. **多维三层画像**：身份层（他是谁）、行为层（他怎么学）、状态层（他现在会什么），每个字段都标注证据来源；
2. **问答成为画像的核心原料**：学生与助教的每一轮对话都被标注、入账，转化为提问构成与逐概念掌握度；
3. **内容级分层教学**：基础薄弱者沿先修链获得补习与巩固，学得快者跳过已掌握内容并获得加深，形成"采集 → 画像 → 课堂改变 → 评估回调"的闭环。

### 1.3 五条贯穿原则

**原则一：分层制——LLM 只做判断，数值由确定性规则演化。** LLM 负责从对话和材料中产生判断（这条提问是概念性还是任务特异？这轮对话涉及哪些概念？学生展示了理解还是误解？），但画像数值（掌握概率、置信度、触发阈值）的每一步演化都由确定性规则完成。理由：可复现、可单测、可审计、可纠错。教师或学生质疑"为什么说我这个没掌握"时，系统必须能回放证据链；这是 LLM 直出画像数值永远做不到的。OpenMAIC 的"LLM 观察、代码计分"模式是这个原则的雏形，本设计把它从单轴难度推广到整个画像层。学术证据同向：专门的知识追踪模型在估计学生状态上优于通用 LLM 直接估计。

**原则二：每个画像字段必须标注证据来源。** 任何一个画像字段都必须能回答"它由哪类采集事件喂养"。没有证据来源的字段不允许存在——这是防止画像膨胀成"听起来很美但无据可依"的字段清单的纪律（借鉴自人格画像研究的"维度必须对话可观察"原则）。

**原则三：采集与画像一体设计，信封先行。** 先立统一事件信封，再谈采集清单；所有指标（课程时长、活跃天数、完成率）从信封派生，不单独埋点。反面教材是 MAIC 论文宣称的"10 万+ 行为记录"——连字段定义都未曾给出，采集随意等于后期无米下锅。

**原则四：教师在环，但只做审校与聚合消费。** 教师审校知识图谱、抽检 LLM 打标、固化高频补习模块、按回调报告校准阈值；教师不看学生的个人对话原文，不直接编辑画像数值。AI 做体力活，教师做质量兜底。

**原则五：学生主体性不可剥夺。** 主线内容对所有学生始终可见，补习是插入不是替换；学生的显式声明（"这个我早会了"/"完全不懂"）是强证据；学生能看到自己的概念掌握地图。分层教学是服务，不是分班。

### 1.4 对照：MAIC 论文宣称 vs OpenMAIC 开源现实

| 环节         | 论文宣称                                                  | 开源现实                          | 本设计的态度                             |
| ------------ | --------------------------------------------------------- | --------------------------------- | ---------------------------------------- |
| 认知学生建模 | 对话 agent 采集学术+情感特征，摘要 agent 产结构化标签画像 | 缺失，退化为手填简介 + 单轴熟练度 | 三层画像，对话是核心原料                 |
| 个性化       | token 级改写（检索+Bloom/ZPD/UDL 润色）                   | 缺失，仅档位注入提示词            | L1 策略查表为地基，L2 内容级插拔为主目标 |
| 行为分析     | 七类学生活动、MsgNum/MsgLen 与成绩相关                    | 原始数据可支撑，无分析层          | 会话末打标 + 行为构成进画像              |
| 实证         | 个性化仅经合成画像专家评估，无 on/off 对照                | —                                 | 机制健康层 + 观察性指标，预留分桶能力    |

## 第 2 章 交互采集层

采集层回答"记录什么"。设计立场：**采集是画像的原料采购，不是行为监控**——只采有明确画像用途的信号，凡是写不出画像消费方的字段一律不采。

### 2.1 事件信封与派生层原则

所有采集事件共用一个统一信封：

```
{ 事件ID, 学习者ID, 会话ID, 时间戳, 课程ID, 资源定位, 事件类型, 载荷 }
```

- **资源定位**是关键字段：视频精确到秒位、PPT/PDF 精确到页码、测验精确到题目、对话精确到当时的课件位置。没有资源定位的事件无法挂接到概念图谱，也就无法喂养画像。
- **会话ID** 串起一次连续学习过程，是"首看/重看""学习节奏"等派生统计的分界。
- 原始事件流只追加、不修改、可重放。任何指标都可以事后重算。

**派生层原则**：课程总时长、每周活跃天数、视频完成率、首次作答正确率（CFA）等一切聚合指标，一律从事件信封派生计算，不单独埋点。派生逻辑可以改（换了算法重算即可），原始事件不动。这条原则的代价是零，收益是指标体系永远可以演进。

### 2.2 问答对话采集：全量原文 + 上下文

学生与 AI 助教的问答是全部采集面中最富的信号源，采到最细：

- **每条消息存全文**（学生消息与助教回复都存），带时间戳与会话 ID；
- **每条消息带课件上下文**：学生提问时学到哪里——哪个视频的第几秒、哪页 PPT/PDF、对应哪个（些）概念；
- **学生点选课件元素提问时，记录被引用元素**（"这个公式为什么成立"中的"这个"指什么）；
- **对话行为标签不在采集时打**：提问类型分类、涉及概念标注、理解/误解判定全部是会话末批量计算的派生层（机制见第 3 章）。采集层只保证原料完整、上下文齐全。

为什么坚持全量原文：OpenMAIC 的教训正在于此——它也存了全量对话，却只让 LLM 在服务当下对话时顺便消费，从未系统地转化为画像；它的画像数值只认结构化标签，等于把最富的信号源闲置了。学术研究（StudyChat 对 16,851 条真实学生-AI 对话的分析）证明对话文本里埋着与成绩显著相关的行为结构；知识追踪研究进一步证明从对话原文直接估计逐知识点掌握是可行的。原文是所有这些机制的共同原料，且只有原文能在未来支撑还没想到的用法。

### 2.3 视频行为采集

直接采用 xAPI Video Profile 的成熟子集（行业标准，无发明成本）：

- **事件**：播放、暂停、拖动（带起止位置）、完成、倍速变更；
- **观看区间（played-segments）**：在暂停/拖动/完成/页面隐藏时事件驱动地记录本次会话已看区间，不做定时心跳。观看区间是最高价值的派生原料：由此可算完成率、生成观看热区、区分首看与重看；
- 每条事件带会话 ID；浏览器标签页切换/隐藏时记一次暂停（可见性过滤的入口）。

**判读纪律**（写进派生层，不写进采集层）：

- **首看与重看必须分开统计**。学习分析的经典研究（edX 秒级日志）表明：重看会话的"退出率"远高于首看，因为重看者是带着明确目的的选择性观看；重看热区往往标记"困惑点"或"兴趣点"，对群体是课程质量信号，对个体要结合上下文解读，不能直接定性为"没学会"。
- **开头瞬时退出按噪声过滤**（大量是自动播放或误点）。
- **倍速不作负面解读**：≤2x 倍速对理解测验成绩无显著损害，且绝大多数本科生常用倍速。倍速偏好可以作为行为层的弱特征，但不作掌握度证据。

### 2.4 课件行为采集（PPT/PDF）

- **底线**：页级翻页事件 + 页级可见停留时长（经可见性过滤——标签页失焦不计时）。
- **顺带**：若播放器已支持学生主动高亮/批注，则采集（主动标注是强投入信号）；不为此专门开发功能。
- 停留时长的有效性有明确文献边界：**细粒度（页级）+ 可见性过滤**才与表现弱相关，粗粒度时长（页面挂着不走）无意义。PDF/PPT 阅读器内更细的行为（缩放、文本选择）没有行业标准，本设计不采。

### 2.5 测验过程采集

OpenMAIC 只记录"草稿→提交→已评"三阶段与对错，不记录过程。本设计逐题采集：

- 题目 ID、所选答案、对错、**逐题用时**；
- **答案修改轨迹**：修改前后的选项 + 修改次序。

修改轨迹必须带次序，因为证据明确：首次修改方向（错→对约占 48–55%）是有效的元认知信号，第二次及以后的修改基本是噪声。逐题用时 + 首次作答正确率（CFA）是 MOOC 学习分析中复现性最好的过程特征族成员。

### 2.6 明确不采清单

光标轨迹、滚动深度、鼠标移动：噪声大、文献无价值共识、隐私敏感度高。写下"不采什么"是为了防止埋点膨胀——每个新增字段都必须重新过"画像消费方是谁"的审查。

### 2.7 学习者身份与数据边界

- **账号制**：学生登录使用，画像跨设备、跨会话连续。OpenMAIC 用匿名设备 key，换设备即断——对"画像随学习演进"的设计目标是致命的，故弃用。
- **问答原文属敏感数据**：默认保留供画像计算，学生可请求删除；存储上与派生的画像字段分离。
- **教师边界**：教师只见聚合层与个体掌握地图，永远不见个人对话原文与行为标签（详见第 6 章教师端视图）。

### 2.8 与 OpenMAIC 的采集面对照

| 采集面   | OpenMAIC                                      | 本设计                                            |
| -------- | --------------------------------------------- | ------------------------------------------------- |
| 对话     | 全量消息 + 课件状态快照随消息携带（存而不用） | 全量原文 + 上下文，会话末系统转化为画像（存且用） |
| 视频     | 不涉及（其课堂为 agent 授课，非视频课件）     | xAPI 子集 + 观看区间 + 首看/重看分离              |
| 课件浏览 | 不采翻页与停留                                | 页级翻页 + 可见停留                               |
| 测验     | 三阶段状态 + 对错，无过程数据                 | 逐题用时 + 修改轨迹（含次序）                     |
| 学习事件 | LLM 课堂内实时打观察标签（错误/卡壳/提问）    | 会话末批量打标（带全上下文，质量更高、成本更低）  |
| 身份     | 匿名设备 key                                  | 账号制                                            |
| 埋点哲学 | 事件由服务端 agent 产生                       | 事件信封统一承载，指标全部派生                    |

OpenMAIC 有两个值得继承的采集设计：一是**事件产生于服务端 agent 而非前端埋点**的思路（本设计将其改造为"会话末批量打标"）；二是**只追加、可重放的事件账本**（本设计的事件信封与之同构）。

## 第 3 章 学生画像层

画像层回答"原料怎么变成学生模型"。这是本设计相对 OpenMAIC 增量最大的一层。

### 3.1 三层骨架：字段、形状与证据来源

画像 = 身份层 + 行为层 + 状态层。三层分别回答"他是谁""他怎么学""他现在会什么"。**每个字段都标注证据事件类型**（原则二），下表即画像的完整 schema（MVP 范围）：

**身份层（静态，低频更新）**

| 字段       | 形状                 | 证据来源                    | 用途限定                                       |
| ---------- | -------------------- | --------------------------- | ---------------------------------------------- |
| 课程身份   | 年级/专业/先修课自述 | 入课自报对话                | 冷启动先验 + L1 语境化，**不作难度判断主依据** |
| 兴趣标签树 | 域/类/关键词三级标签 | 入课自报对话 + 阶段末重提炼 | L1 举例与类比的素材库                          |

**行为层（构成向量，会话末更新）**

| 字段       | 形状                                               | 证据来源               | 含义                                                       |
| ---------- | -------------------------------------------------- | ---------------------- | ---------------------------------------------------------- |
| 提问构成   | 概念性提问 vs 任务特异提问的比例（滚动）           | 会话末打标（对话原文） | 最强预测轴：概念性提问与成绩正相关，任务特异求助是困惑信号 |
| 投入度聚合 | 每周活跃天数、视频完成率、首看/重看比              | 视频/课件事件派生      | MOOC 预测中复现性最好的特征族                              |
| 测验过程   | CFA（首次作答正确率）、首次修改方向                | 测验事件派生           | 元认知信号                                                 |
| 求知欲     | 弱信号分（主动提问频次、概念性提问占比、主动重看） | 派生                   | 加速 vs 加深的分流依据                                     |

**状态层（动态估计，测验即时 + 会话末更新）**

| 字段         | 形状                                                | 证据来源                    | 含义                         |
| ------------ | --------------------------------------------------- | --------------------------- | ---------------------------- |
| 逐概念掌握度 | 每概念 `{掌握概率 0–1, 置信度, 证据计数, 最近更新}` | 测验逐题作答 + 对话理解标注 | 补基础/加速/加深的全部触发源 |
| 学习速度     | `{单位活跃时长掌握概念数, 每概念平均练习轮次}`      | 掌握度历史派生              | 区分"掌握得快"与"慢慢磨会"   |

设计说明：

- **提问构成是行为层的第一公民**。StudyChat 的证据表明，提问的对象（指向通用概念 vs 指向当前作业/任务）是比消息数量、消息长度值钱得多的切分轴； OpenMAIC 只统计了消息量（对应论文的 MsgNum/MsgLen），恰好丢掉了这个轴。
- **求知欲单列**是因为 T5 的分流逻辑需要它：掌握度高且求知欲高的学生给加深，掌握度高但求知欲低的学生只加速。它是从已采事件派生的弱信号，不做专门的情感检测（显式情感检测——困惑/挫败识别——需要专门检测器，投入产出比在单课程场景不成立，放远期）。
- **学习速度用绝对度量**（单位活跃时长掌握概念数、每概念平均练习轮次），不用班级百分位——单课程初期没有稳定的对照群体，且百分位会把"全班都快"误判成"没人快"。
- 更细的 31 类对话行为完整分布（写作/编辑/验证/闲聊等）放远期：LLM 打标的一致性已被文献证实（人-机一致度与人类间一致度持平），技术上没有障碍，但 MVP 先把最有预测力的轴做扎实。

### 3.2 构建机制：分层制的运转

**LLM 与画像的边界**：LLM 只做三类判断——① 每条学生提问的类型（概念性/任务特异/其他）；② 每轮对话涉及的概念（挂到知识图谱的概念 ID 上）；③ 该轮学生展示的是理解还是误解（针对所涉概念）。画像数值的演化全部由确定性规则完成。系统拒绝让 LLM 周期性读对话直接输出画像数值——那样的画像无法解释、无法回放证据、无法纠错，违背原则一与原则二。

**打标时机：会话末批量**。每次学习会话结束时，LLM 带完整上下文对该会话的对话批量打标，结果入账。对比 OpenMAIC 的"课堂内实时打观察标签"：批量打标能看到完整会话（判断"学生最后懂了没有"需要看后文）、调用成本更低、失败可重跑。课中的即时适应不走画像管道——助教在对话进行中的即时反应由对话上下文直接支撑（见第 5 章 L1），画像不背实时压力。

**掌握度模型：BKT（贝叶斯知识追踪）**。每个概念一个掌握概率，两路证据入账：

1. **测验逐题作答**：每题标注所属概念（图谱的题目映射），对错直接更新对应概念；
2. **对话理解标注**：会话末打标产出"涉及概念 × 理解/误解"，作为较弱权重的证据更新。

BKT 的参数（猜对率、失误率、学习率）用经验先验起步，不需要训练管线；远期积累数据后可换更强的专门知识追踪模型（升级路径：经验参数 BKT → 拟合参数 → 专门 KT 模型）。相对 OpenMAIC 的单轴滑动平均档位，这是从"一个数"到"逐概念向量"的跨越——"补基础"因此能精确到概念，而不是笼统地降难度。

**更新时机汇总**：测验提交 = 立即更新（结构化数据，零延迟）；对话标注 = 会话末批量更新；行为层聚合 = 会话末派生重算；学习速度 = 滚动窗口派生（证据不足时不显示）。

### 3.3 冷启动：新生第一课的画像从哪来

- **入课自报对话（必做）**：一个简短的对话式采集（年级、专业、先修课、兴趣），是身份层的唯一来源。借鉴 PAGE（MAIC 论文 3.2 的展开工作）的成熟做法：固定开场、必答项追问、每兴趣限一次追问、用户确认后生成画像。
- **摸底诊断测验（建议做）**：教师从题库组 10–15 题覆盖主干概念，直接喂 BKT 先验——让"补基础/加速"从第一节课就可用，而不是等学生暴露问题。
- **默认兜底**：未被摸底覆盖的概念，掌握概率取中值、置信度取低，等证据说话。

### 3.4 置信度与纠错

- **置信度 = 证据计数 + 时间衰减的确定性函数**：证据越少、越久未触碰，置信越低。低置信的概念不触发任何教学动作（宁可不动作，不可错动作）。
- **学生显式声明 = 强证据**："这个我早会了"/"完全听不懂"按高权重直接入账（OpenMAIC 验证过的做法：学生说明文难度诉求时视为 ground truth）。
- **画像的自我修正通道**：被标弱的概念在后续测验中仍会抽样出现（"再挑战"机制，见第 5 章护栏），证据会持续冲刷旧判断。
- **教师不直接改数**：MVP 阶段教师不能直接编辑画像数值，只能通过修正知识图谱、题目标注、模块挂接来间接纠错——保住画像的可审计性。教师直接编辑放远期。

### 3.5 身份层的周期性重提炼

身份层是自述型数据，会过时（兴趣会变、背景认知会修正）。每个学习阶段末（如每模块结束），摘要 agent 重读近期对话，重提炼一次身份/兴趣标签；**更新前把摘要给学生看，学生确认后生效**（"修正优先"原则：学生纠正过的内容以最终版为准）。状态层与行为层是纯增量入账，不需要也不使用这种全量重提炼。

### 3.6 学生可见性

- **可见**：概念掌握地图（知识图谱上的简化掌握热力——学生能直观看到"我哪弱"，自我导向复习，也让明显错误的画像有机会被学生发现）、进度与投入摘要（活跃天数、完成率）。
- **不可见**：置信度内部值、提问行为标签与构成分析。行为标签一旦公开就会成为刷取目标（"显得爱提问"），指标即失效——这是古德哈特定律的直接应用。

### 3.7 与 OpenMAIC 的画像层对照

| 维度     | OpenMAIC                       | 本设计                                     |
| -------- | ------------------------------ | ------------------------------------------ |
| 画像结构 | 单轴难度档 + 手填简介          | 三层骨架（身份/行为/状态），字段级证据来源 |
| 问答对话 | 存而不用                       | 会话末打标，提问构成 + 概念理解双路入账    |
| 掌握度   | 单轴滑动平均，方向分硬编码     | 逐概念 BKT，证据两路（测验+对话）          |
| 兴趣情感 | 手填 bio 注入提示词            | 兴趣标签树（自报+周期重提炼），限定用途    |
| 冷启动   | 无（画像全靠手填）             | 自报对话 + 摸底测验 + 默认兜底             |
| 可见性   | 对学生不可见                   | 掌握地图可见，行为标签不外露               |
| 继承之处 | "LLM 观察、代码计分"的分层思想 | 继承并推广到全画像层（原则一）             |

## 第 4 章 内容地基：知识图谱与模块体系（略写）

L2 内容级自适应的前提是课程内容可被拆换。三件事：

- **概念知识图谱**：每门课 100–300 个概念节点 + 先修有向边（专管跨章节先修关系，章节树保留为组织外壳）。**AI 从教师上传材料自动抽取，教师发布前审校**（教师只看低置信边与主干链，角色是审校者不是录入员）。**图谱版本化**：概念 ID 稳定，修改 = 新增/废弃而非改写——画像证据挂在概念 ID 上，图谱迭代不得毁掉既有画像。
- **两张映射**：概念 → 材料片段（视频区间/PPT 页/PDF 段落，补基础时指回原文重看）；概念 → 测验题（BKT 的证据入口）。
- **模块体系**：模块 = 单概念或 ≤3 概念小簇，类型为讲解/练习/讨论，标注层级（补基础/标准/深化），统一挂概念 ID 供策略引擎调用。**补习模块**由 AI 基于材料生成（讲解 + 重看指引 + 2–3 题巩固练习），高频触发模块由教师审校固化；**深化模块** MVP 只做课内加深（高阶概念前置 + 进阶练习/讨论，事实性有课程材料兜底），开放外拓（前沿论文等）放远期。

## 第 5 章 分层教学策略：L2 闭环（略写）

**触发是确定性规则引擎**（阈值+置信度+冷却），LLM 只负责动作内容。三态：

- **补基础**：双通道触发——学新内容前沿先修链检查依赖概念（掌握 <0.6 且置信足够，事前预防）；当前概念测验错误或对话标注误解（事后补救）。动作 = 插入补习模块 + 助教进入补基础态。**插入不是替换，主线始终可见**。补后测通过即回主线；两轮未过沿先修链再降一层，同时该概念进入教师聚合视图（群体卡点是课程问题）。
- **加速**：掌握 ≥0.85 且置信足够 → 标准讲解替换为摘要卡 + 3 题快速确认测，通过即跳过（确认测是防掌握度高估的闸口）。
- **加深**：掌握高**且求知欲高** → 追加深化模块 + 助教加深态。掌握高但求知欲低 → 只加速不加深。
- **L1 助教策略查表**（三态共用）：补基础态更慢更多例子、提示式引导优先于直接给答案（证据：提示式回应显著提升学习率，直接给答案为负）；加速态精简；加深态苏格拉底反问；全程兴趣类比。
- **防标签固化四护栏**：置信度+时间衰减；学生声明强证据；插入不替换；被标弱概念后续测验抽样再现（再挑战通道）。

## 第 6 章 闭环评估（略写）

- **三层指标**：学习成效层（掌握度曲线、达标耗时、阶段成绩）；机制健康层（补习触发率、补习后回归成功率、加速确认测通过率、深化模块完成率——这一层负责发现"自适应系统自己病了"：阈值病/模块病/画像病）；体验层（投入度趋势、概念性提问占比变化）。
- **节奏**：机制健康层持续可查，三层指标每模块末例行回顾，课程结束整体评估。
- **第二阶闭环**：阈值校准（0.6/0.85 为待校准初始值）、LLM 打标小比例人工抽检、低回归率模块进教师队列。MVP 由教师在环执行，不做自动调参。
- **严谨度立场**：观察性指标 + 透明口径起步，不设对照组（样本量与伦理双重原因）；存储预留按学生分桶开关策略的能力，A/B 放远期。
- **教师端视图（MVP）**：班级聚合三件套（卡点概念排行、三态触发统计、全班掌握热力）+ 个体掌握地图；不见对话原文与行为标签。

## 第 7 章 分期路线（略写）

**MVP**（第 0 章速查表已汇总）：采集四族 + 信封；三层画像 + BKT + 冷启动；图谱 + 补习/深化模块；三态策略；三层指标 + 教师端视图。

**远期项与启动条件**：

| 远期项                | 启动条件                                   |
| --------------------- | ------------------------------------------ |
| L3 路径级大纲重排     | 加速/补基础高频发生，内容级插拔显局促时    |
| 开放外拓深化模块      | 课内加深被反复触发且学生要求超出课程范围时 |
| 显式情感检测          | 有明确证据显示困惑/挫败导致流失时          |
| 31 类完整对话行为分布 | 提问构成轴验证有效、需要更细行为画像时     |
| 专门 KT 模型          | 积累足量标注数据、BKT 拟合不足时           |
| 分桶 A/B              | 学生规模达到统计功效要求时                 |
| 教师直接编辑画像      | 教师端使用成熟、出现明确误判诉求时         |

## 第 8 章 与 OpenMAIC 的总对照

### 8.1 六维对照总表

| 维度       | MAIC 论文（宣称）              | OpenMAIC（开源现实）                        | 本设计                                                    |
| ---------- | ------------------------------ | ------------------------------------------- | --------------------------------------------------------- |
| 交互采集   | 10 万+行为记录（无字段定义）   | 消息+课件快照、engagement 账本、quiz 三阶段 | 统一事件信封四族采集，问答全量原文+上下文，测验带过程数据 |
| 画像维度   | 学术+情感结构化标签            | 手填简介 + 单轴难度档                       | 身份/行为/状态三层，逐概念掌握度+学习速度+提问构成        |
| 建模技术   | 对话 agent + 摘要 agent        | LLM 观察 + 确定性滑动平均                   | 分层制：会话末 LLM 打标 + BKT 确定性入账                  |
| 问答利用   | 未打通（画像只服务改写）       | 存而不用                                    | 核心原料：提问构成、概念理解双路入账                      |
| 个性化层级 | token 级改写（不改变教学内容） | 档位注入提示词                              | L1 三态策略查表 + L2 内容级插拔（补/跳/加深）             |
| 闭环       | 未做 on/off 对照，证据链断裂   | 无评估层                                    | 三层指标 + 第二阶闭环，阈值可校准                         |

### 8.2 我们继承了什么

- **"LLM 观察、代码计分"的分层思想**：OpenMAIC 最有价值的工程直觉。LLM 不碰数值，数值演化确定性——我们把它从单轴熟练度推广到整个画像层，并升级为 BKT。
- **只追加、可重放的事件账本**：与其运行时记录的设计同构，我们前置为统一事件信封。
- **服务端 agent 产生学习事件的思路**：我们把"课堂内实时打标"改造为"会话末批量打标"，更省、更准、可重跑。
- **学生显式声明即 ground truth** 的纠错通道，原样继承。
- **论文侧**：PAGE 的自报对话与摘要重提炼、提示式引导优于直接给答案的教学策略证据、概念性/任务特异提问的切分轴，都直接进入了本设计的对应层。

### 8.3 我们修正了什么

- **画像深度**：从"单轴难度 + 手填身份"到三层多维。OpenMAIC 的画像回答不了"他哪里弱、为什么弱、学得多快"，本设计的状态层与行为层就是为此而立。
- **问答利用**：OpenMAIC 与论文都把对话当上下文而非数据。本设计把问答对话放在采集面与画像层的正中央——这是对"存而不用"的正面修正，也是对用户最初痛点的正面回答。
- **个性化层级**：token 级改写改变的是措辞，课堂内容本身不变。本设计以内容级插拔为主目标：补基础沿先修链精确到概念、加速有确认测闸口、加深按求知欲分流。L1 对话级调整作为三态策略的副产物自然落地，不另起炉灶。
- **评估**：论文的个性化证据链是断的（合成画像评内容质量、真实日志算行为相关，两段从未连接）。本设计的机制健康层把"自适应系统本身是否工作"变成持续可答的问题，第二阶闭环让阈值与模块质量可以随数据回调。

### 8.4 我们新增了什么

- **概念知识图谱 + 模块体系**（论文主张、开源缺失的内容地基，以"AI 抽取 + 教师审校 + 版本化"落地）；
- **机制健康层指标体系**（把自适应系统自身纳入监控）；
- **求知欲分流**（加速与加深的分离，OpenMAIC 的单轴结构在原理上无法表达）。
